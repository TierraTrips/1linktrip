Message emails (optional)

Emails the host when a guest writes, the guest when the host replies, and guests when an update is posted for them. Messages already show in the app without this.

1. Database

  1. Run database setup, part 3 if you haven’t.

2. The function

  1. Tap Copy function → Supabase → Edge Functions → Deploy a new function → Via editor → name notify → paste → Deploy. Leave Verify JWT on.
  2. Edge Functions → Secrets → add RESEND_API_KEY (your Resend key, the same re_… one from sign-in emails works).

3. Your domain (when ready)

  1. Until a domain is verified in Resend, emails come from onboarding@resend.dev and Resend only delivers them to your own Resend email.
  2. After you add and verify a domain in Resend → Domains, add the secret NOTIFY_FROM = 1LinkTrip <hello@yourdomain.com>. No code change needed.

4. Invitations (Guest list → Invitations)

  1. Run supabase/schema-invites.sql (designs, sends, the invitations picture bucket).
  2. Your plan’s email allowance: secrets NOTIFY_DAILY_CAP (default 100) and NOTIFY_MONTHLY_CAP (default 3000); NOTIFY_RESERVE (default 10) is kept back each day for sign-in links and messages. Raise the caps when you upgrade Resend — no code change.
  3. Emails over the day’s allowance go out the next day by themselves: add the secret NOTIFY_CRON_SECRET (a long random string), put the same string in Vault as notify_cron_secret and the anon key as notify_anon_jwt, then run supabase/schema-invites-cron.sql. Without it, organizers get a Send the rest now button.
  4. Delivered / bounced: deploy ai/invite-hook.ts as invite-hook with Verify JWT off, add a Resend webhook to it (email.delivered, email.bounced, email.complained) and its signing secret as INVITE_HOOK_SECRET.
